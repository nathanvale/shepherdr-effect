# Adapter seams

The adapters of [module-map.md](module-map.md), built on 19 November 2026 as
seams that compile: an Effect service for each, with its interface, its
tagged errors, a real `layer` and a `layerTest`. Words follow
[GLOSSARY.md](../../GLOSSARY.md). Nothing here reaches an outside system yet.

- Each real `layer` answers the tagged error `NotBuilt` for every entry,
  naming the seam and the entry (`src/adapters/not-built.ts`). `NotBuilt` is in
  every entry's error type until that entry is built.
- Each `layerTest` keeps its state in memory and behaves. Most have a
  `layerTestWith(script)` beside them, for seeded state and scripted failures.
- Import (`src/state-files/`) is already built. Window is not designed.
- What the CLI kernel journal assumes about the kernel, what the design
  notes disagree on, and the types still waiting for a home in the domain
  core are in [adapter-seams-open.md](adapter-seams-open.md).

## The launch rule at the two seams

What [launch-admission.md](launch-admission.md) decided, as these two seams
hold it. Each line has a test.

| Rule                                                                | Held by                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A run other than the attempt owner closes only after it has stopped | `close` answers `AttemptOwnerMayBeRunning` to the person and the scheduler until then. The attempt owner's own closure is not asked. The kernel proves the stop; the seam carries the answer.                                                                                                                                                                                                            |
| Only the person closes an Uncertain launch as completed             | A completed closure names who closes: `person` or `scheduler`. The scheduler's evidence confirms only an effect keyed by the attempt id; for any other effect not yet Confirmed it is `CallerMayNotClose`.                                                                                                                                                                                               |
| A closer finishes only the task assignment                          | An intent declares each effect with `keyedByAttemptId`. A closer's positive evidence confirms an effect that never started only when that is true. Otherwise the refusal is `EffectNotStarted`.                                                                                                                                                                                                          |
| The person refutes an Uncertain launch only on refuting evidence    | The person's `not-applied` closure carries refuting evidence by effect. It goes through `Refute`. Without it the closure is refused as `UncertainNeverCancelled`. The attempt owner's closure has none.                                                                                                                                                                                                  |
| Seeing no labelled terminal is not evidence                         | `observeLaunch` answers positive evidence for exactly one labelled terminal and `Unobservable` otherwise. It has no answer that means "nothing started".                                                                                                                                                                                                                                                 |
| Only a request that was never sent refutes a launch                 | `HerdrCoreUnavailable` says `not-sent` or `unanswered`. The real link answers `not-sent` only when nothing of the request was written to the socket, and `unanswered` whenever that is in doubt. `observeStartReply` makes refuting evidence from `not-sent` or a permit no maker made, and `Unobservable` from `unanswered` or from a permit refused because its attempt id already started a terminal. |
| An interrupted effect ends its herdr-core request                   | `startTerminal` stops at once when interrupted and gives up its reply. This is about the link alone: herdr-core may still start the terminal, and `observeLaunch` then finds it.                                                                                                                                                                                                                         |

`observeStartReply` is a function beside the link's entries, not an entry.

The real link must spend every send permit with `spendSendPermit`, as the test link
does, so that a second start for one attempt id is refused there too.

## Interface counts against the module map

- `HerdrCore` has 14 where the map says about 15. `typeInto` covers
  `terminal.send`, `terminal.keys` and `terminal.interrupt`.
- `GitHubForge` has 4 where the map says 3. [completion.md](completion.md)
  made GitHub publish in stages too, so it needs `observeStage` as Bitbucket
  does.
- `ModelProviders` has one entry, since only Azure's deployment list is
  designed.

## The three invariants held here

| Invariant                                               | Held by                                                                                                                                                                                                                                                                       | Proof                                                                                                                   |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| A terminal start takes a send permit                    | `startTerminal(permit, start)`. `SendPermit` has a private constructor and a private field. The link spends one permit for each attempt id and writes the `herdr.launch` label from the permit.                                                                               | Types, and tests: a spent permit, a second permit for the attempt id, and a look-alike all start nothing.               |
| The Bitbucket forge has no merge                        | `BitbucketForge`'s interface has three entries. `merge` takes a matched repository of forge kind `github`.                                                                                                                                                                    | Types, and a test that lists the entries of the service each layer builds.                                              |
| The store changes only inside `transact`, one at a time | `put` and `remove` exist only on the `StoreTransaction` that `transact` hands its function. That function is synchronous and returns a `Result`: nothing can be awaited inside it, and a refusal records nothing. A transaction kept after `transact` returned throws on use. | Types, and tests: a refused transaction leaves no row, fifty at once lose no count, a kept transaction changes nothing. |

### How a send permit is made

- `SendPermit` cannot be built or imitated outside
  `src/adapters/herdr-core/send-permit.ts`: its constructor is private, and its
  private field makes any other object the wrong type.
- The one maker is the Effect service `SendPermitMaker`. Its `make` takes an
  Uncertain attempt, which `CliKernelJournal.record` hands to the effect only
  after `effect-started` is recorded.
- A procedure that makes a permit must require `SendPermitMaker`, and that
  shows in its type. `src/app/layers.ts` is not built. It is to give
  `SendPermitMaker.layer` to launch admission alone, so that any other
  procedure that requires it leaves the layer graph with a requirement nobody
  provides.
- At run time the link accepts only a permit the maker made, and only one start
  for each attempt id from one `SendPermitMaker`. That refuses a value forced to
  the type with a cast, a permit used twice, and a second permit for an attempt
  id that has started a terminal.
- Not held by a type: a module that imports `SendPermitMaker.layer` and
  provides it to itself. The layer rule already gives adapters' Layers to
  `src/app/layers.ts` alone; the lint rule that enforces it is not built.
