# Issue tracker: Linear

Issues and specs for this repository live in Linear, in the team
`myagentdojo` (issue keys start with `MAG-`), project `Agent ecosystem`.

Use the Linear tools the session provides. This repository has no Git remote,
so there are no GitHub issues and no pull requests to treat as requests.

## Conventions

- **Create an issue**: search the team first for one that already covers it.
  Create it in the team and project above, with one `kind/` label that fits.
- **Read an issue**: read its description and labels, then its comments.
  Comments are fetched separately from the issue.
- **Apply or remove a label**: add or remove that one label. Never replace the
  whole label set.
- **Close**: move the issue to Done or Canceled, with a comment that says why.

## Authority

Creating or changing a Linear issue is a write to an outside service. It needs
Nathan's say in the session. A delegated worker drafts the issue and returns
it as a proposal; the foreground session publishes it.

## When a skill says "publish to the issue tracker"

Create a Linear issue, after the search above.

## When a skill says "fetch the relevant ticket"

Read the issue, its labels and its comments.

## Wayfinding operations

- **Map**: one parent issue that holds the notes and the decisions so far.
- **Child ticket**: a sub-issue of the map.
- **Blocking**: Linear's own blocking relations between issues.
- **Claim**: assign the issue to yourself as the session's first write.
- **Resolve**: comment with the answer, then move the issue to Done.

## Pull requests as a triage surface

**PRs as a request surface: no.**
